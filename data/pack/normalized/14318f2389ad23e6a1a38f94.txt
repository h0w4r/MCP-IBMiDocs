Add Admin Domain MRE (ADDCADMRE)

Add Admin Domain MRE (ADDCADMRE)

Last Updated: 2025-04-08

Where allowed to run: All environments (*ALL)

Threadsafe: Yes | Parameters

Examples

Error messages

The Add Cluster Admin Domain MRE (ADDCADMRE) command is used to add a monitored resource entry (MRE) to a cluster administrative domain. A monitored resource is a system object or a set of attributes not associated with a specific system object, such as the set of system environment variables. A resource represented by an MRE is monitored for changes by a cluster administrative domain. When a monitored resource is changed on one node in a cluster administrative domain, the change is propagated to the other active nodes in the domain.

When adding an MRE for a system object, the resource name is the name of the system object. One or more attributes can be specified. Only attributes that are specified will be monitored for changes.

This command will do the following:

- Create a monitored resource entry on all active nodes in the cluster administrative domain.

- The resource being monitored by the cluster administrative domain will be created on all active nodes in the cluster administrative domain where it does not already exist. The attributes for the created resource will be set to the values of the attributes from the monitored resource on the node specified in the command.

- If the cluster administrative domain has been started, the values of the attributes for the monitored resource will be synchronized to the same attribute values from the monitored resource on the node specified in the command.

- If the cluster administrative domain has not been started, the attribute values for the monitored resource will not be synchronized until the cluster administrative domain is started.

- For nodes in the cluster administrative domain that were not active at the time the command was called, the resource will be created when clustering is started on those nodes.

Restrictions:

- You must have input/output system configuration (*IOSYSCFG) special authority on all nodes in the recovery domain to run this command.

- Resources cannot be added to a cluster administrative domain when it is partitioned.

- The monitored resource must exist on the node specified in the command.

- The caller's user profile must exist on all active nodes in the cluster administrative domain.

- All monitored resources must exist in the system base auxiliary storage pool (ASP) except network server storage spaces (*NWSSTG) which must exist in an independent ASP.

- IBM supplied class objects named QARBCLS, QMONCLS, or QLPINSTAL cannot be added as a monitored resource.

- When adding user profiles and with *ALL or PASSWORD in the Monitored attributes (ATTRIBUTE) parameter, the caller's user profile must be granted *ALLOBJ and *SECADM special authority.

- Attribute OBJAUD and AUDLVL for user profiles can be added at cluster version 9.9 or greater.

- When adding user profiles and with OBJAUD, AUDLVL or *ALL in the Monitored attributes (ATTRIBUTE) parameter, the caller's user profile must be granted *AUDIT special authority.

- Attribute MAXSIGN for user profiles can be added at cluster version 10.9 or greater.

- Attribute SNMPUSR and SNMPCNTX for printer device descriptions can be added at HA version 5.5.2 or greater.

Monitored resource (RESOURCE)

Specifies the resource to be monitored.

This is a required parameter.

*ALL
Specify that all monitored resources of the specified monitored resource type (RSCTYPE) are to be added to the administrative domain. This special value cannot be used in batch mode.
This special value is only allowed for the following monitored resource types:

- *USRPRF

- *AUTL

- *CLS

- *JOBD

- *SBSD

generic-resource-name
Resources that meet the criteria are selected. A generic resource name is a character string that contains one or more characters followed by an asterisk (*); for example, ABC*. The asterisk substitutes for any valid characters. If an asterisk is not specified with the resource name, the system assumes that the resource name is a complete resource name. This special value cannot be used in batch mode.
A generic name is only allowed for the following monitored resource types:

- *USRPRF

- *AUTL

- *CLS

- *JOBD

- *SBSD

Examples for ADDCADMRE

Example 1: Adding an MRE for a job description

ADDCADMRE RESOURCE(MYJOBD) RSCTYPE(*JOBD) RSCLIB(QGPL)
ATTRIBUTE(*ALL)

This command adds a monitored resource entry for a job description named MYJOBD in library QGPL. The monitored resource is provided from the local node. Any change to the job description will be monitored by the cluster administrative domain which the local node is part of.

Example 2: Adding an MRE for a user profile

ADDCADMRE RESOURCE(MYPROFILE) RSCTYPE(*USRPRF)
ATTRIBUTE(PASSWORD)

This command adds a monitored resource entry for a user profile named MYPROFILE in library QGPL. The monitored resource is provided from the local node. Changes to the PASSWORD attribute will be monitored by the cluster administrative domain which the local node is part of.

Example 3: Adding multiple resources of one type

ADDCADMRE RESOURCE(*ALL) RSCTYPE(*USRPRF)

This command adds all user profiles to the administrative domain for the local node. All the user profiles on the local node will be listed on the screen, and any user profiles that should not be in the administrative domain can be removed from the list manually. Confirmation is needed for the user profiles to be added to the administrative domain.
