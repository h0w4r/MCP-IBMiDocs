CCSID of a subfield defined with EXTFLD when the DS has CCSID(*EXACT)

Last Updated: 2025-10-07

Prior to release IBM® i 7.6, when a character subfield of an
externally described data structure defined with CCSID(*EXACT) was specified with the EXTFLD
keyword, the subfield was defined with the default character CCSID of the module rather than the
CCSID of the field in the file.

This problem did not occur if control keyword CCSID(*EXACT) was specified.

Starting in the base of IBM i release 7.6 for TGTRLS(*CURRENT), the compiler always assigns the
CCSID of character subfields to be the CCSID of the field in the file when the data structure is
defined with the CCSID(*EXACT) keyword.

For target IBM i releases 7.3 to 7.5, you can add environment variable,
QIBM_RPG_FIX_DS_CCSID_EXACT_EXTFLD, with a value of 'Y', to cause the compiler to assign the correct
CCSID to the subfields.
