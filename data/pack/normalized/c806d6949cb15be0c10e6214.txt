Merge Spooled Files (MRGSPLFOND)

Merge Spooled Files (MRGSPLFOND)

Last Updated: 2025-04-08

Where allowed to run: All environments (*ALL)

Threadsafe: No | Parameters

Examples

Error messages

The Merge Spooled Files (MRGSPLFOND) command combines multiple SNA character stream (SCS) spooled files and writes the result to a single spooled file or database file member for Content Manager OnDemand to process. Spooled files to merge must be contained in a single output queue and must be in ready (RDY) status. Spooled files that are not in a Ready (RDY) status and that are not SCS are left in the From output queue (FROMOUTQ).

The first spooled file that is processed is used to define the attributes of the merged spooled file. All subsequent spooled files to merge must have identical attributes. After each spooled file is merged successfully, it is deleted or moved to another output queue where it is optionally placed on hold. The resulting merged spooled file or database file member can also be automatically archived into a specified application group and application within a Content Manager OnDemand instance, after merge processing has completed.

Note: When processing begins, spooled files are selected to merge. Spooled files which are added to the From output queue (FROMOUTQ) after the selection process completes are not merged.

Spooled files that do not have identical attributes to the first spooled file processed are not processed. A message can be written to the job log for each spooled file that is not processed. The message indicates that, due to the attribute difference listed in the message, the spooled file could not be merged. Spooled files that are not processed are left in the From output queue (FROMOUTQ) in RDY status.

Restrictions:

- To merge spooled files, you must have use (*USE) authority to the From output queue (FROMOUTQ), change (*CHANGE) authority to the To output queue (TOOUTQ), use (*USE) authority to the Job description (JOBD) and change (*CHANGE) authority to the database file specified by the To file (TOFILE) parameter (if it already exists). In addition, you need spool control (*SPLCTL) special authority if any of the spooled files to merge were created by jobs running under other user profiles.

- If the Archive merged file (ARCHIVE) parameter is set to *YES, you must be authorized to perform archive processing for the specified Content Manager OnDemand instance.

- Merging of SCS-extended spooled files is not supported.

From output queue (FROMOUTQ)

Specifies the name of output queue containing the spooled files to merge.

This is a required parameter.

Qualifier 1: From output queue

output-queue-name
Specify the name of the output queue where the spooled files are found.

Qualifier 2: Library

*LIBL
All libraries in the library list for the current job are searched until the first match is found.

*CURLIB
The current library for the job is used to locate the output queue. If no current library entry exists in the library list, QGPL is used.

library-name
Specify the library where the output queue is located.

Replace or add records (MBROPT)

Specifies whether the first input spooled file replaces or is appended to the end of the existing records in the merged output file member. Each subsequent input spooled file is appended to the end of the previous records in the output file member. If the output file or member does not exist, it is automatically created. If the TOFILE default library value of *LIBL is specified, and the file does not already exist, it is not automatically created.

*REPLACE
The system clears the existing member and adds the new records.

*ADD
The system adds the new records to the end of the existing records.

Archive merged file (ARCHIVE)

Specifies whether or not to archive the merged output file using the Add Report (ADDRPTOND) command.

When the MRGSPLFOND command is run with OUTPUT(*TOFILE) and ARCHIVE(*YES), after all the spooled files are copied into the To file (TOFILE), the Add Report (ADDRPTOND) command is run with INPUT(*FILE).

When the MRGSPLFOND command is run with OUTPUT(*TOOUTQ) and ARCHIVE(*YES), the spooled files are copied into a temporary physical file, that physical file is copied to a spooled file in the To output queue (TOOUTQ), and the Add Report (ADDRPTOND) command is run with INPUT(*SPLF).

*NO
Specify that the merged file is not archived by using the Add Report (ADDRPTOND) command.

*YES
Specify that the merged file is archived by using the Add Report (ADDRPTOND) command.

Examples for MRGSPLFOND

Example 1: Merge and Archive All Reports with Form Type *STD

MRGSPLFOND FROMOUTQ(QPRINT) OUTPUT(*TOFILE)
TOFILE(QGPL/MERGEDRPT) PRCOUTQ(QGPL/PRT01)
FORMTYPE(*STD) ARCHIVE(*YES) APPGRP(*USERDATA)
SBMJOB(*YES)

This command merges all reports in the QPRINT output queue with form type *STD and places the merged output in a file named MERGEDRPT in library QGPL. After each spooled file is successfully merged it is moved to output queue PRT01 in library QGPL.

After the merge processing has been completed, the merged output is archived by using the Add Report (ADDRPTOND) command. The application group name is obtained from the user data found in the first spooled file that is merged. The archived data is stored in the default instance since no instance name is specified.

All merge and archive processing are run in a separate batch job.

Example 2: Merge up to 500 Checks

MRGSPLFOND FROMOUTQ(PAYABLES) OUTPUT(*TOFILE)
TOFILE(QGPL/CHECKS) MBROPT(*ADD)
PRCOUTQ(QGPL/APCHECKS) HLDPRCSPLF(*YES)
SPLF(CHKSPRTF) USRDTA(PAYABLES) JOB(CHECKS)
NBRFILES(500) ARCHIVE(*NO) SBMJOB(*YES)

This command merges spooled files from the PAYABLES output queue that have been printed with the CHKSPRTF printer file, have user data of PAYABLES and were created by a job named CHECKS. All successfully merged spooled files are appended to the first database file member of the CHECKS file in library QGPL. Only the first 500 spooled files with matching selection criteria are merged. All successfully merged spooled files are moved to the APCHECKS output queue in library QGPL and placed on hold.

All merge processing is run in a separate batch job.

Example 3: Merge and Archive All Reports with Form Type *STD to an Output Queue

MRGSPLFOND FROMOUTQ(QPRINT) OUTPUT(*TOOUTQ)
TOOUTQ(QGPL/ACCOUNTING) PRCOUTQ(QGPL/PRT01)
FORMTYPE(*STD) ARCHIVE(*YES) APPGRP(*USERDATA)
INSTANCE(ACCTING) SBMJOB(*YES)

This command merges all reports in the QPRINT output queue with form type *STD and places the merged output in an output queue named ACCOUNTING in library QGPL. After each spooled file is successfully merged it is moved to output queue PRT01 in library QGPL.

After the merge processing has been completed, the merged output is archived by using the Add Report (ADDRPTOND) command. The application group name is obtained from the user data found in the first spooled file that is merged. The archived data is stored in an instance named ACCTING.

All merge and archive processing are run in a separate batch job.
