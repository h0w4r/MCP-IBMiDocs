Add Report (ADDRPTOND)

Add Report (ADDRPTOND)

Last Updated: 2025-04-08

Where allowed to run: All environments (*ALL)

Threadsafe: No | Parameters

Examples

Error messages

The Add Report (ADDRPTOND) command loads reports into Content Manager OnDemand. During this process, the report is broken into segments, indexed, compressed, and stored on disk for retrieval and later migration to archive media if desired.

Application group (APPGRP)

Specifies the name of the application group used in the load process.

This is a required parameter.

Note: Position the cursor in the application group parameter entry and use the prompt (F4) key to view the list of application group values that are available for the default (*DFT) instance.

The default instance is specified in the QDFTINST data area. The QDFTINST data area can exist in multiple libraries. A search for the QDFTINST data area is performed by using the library list. The first data area that is found is used. If the QDFTINST data area is not found by using the library list, the QUSRRDARS library is searched for the data area. If the data area exists in the QUSRRDARS library, it is used. If the QDFTINST data area is not found, instance QUSROND is used.

For spooled files or directory files:

application-group-name
Specify the application group name.
If the value contains lowercase letters, blanks, or special characters, it must be enclosed in single quotation marks.

*JOBNAME
Use the job name as the source for the application group name.

For spooled files:

*SPLFNAME
Use the spooled file name as the source for the name.

*FORMTYPE
Use the form type as the source for the name.

*USERDATA
Use the user data as the source for the name.

*JOBNAME
Use the job name as the source for the name.

*USRDFNOPT1
Use the user-defined option 1 as the source for the name.

*USRDFNOPT2
Use the user-defined option 2 as the source for the name.

*USRDFNOPT3
Use the user-defined option 3 as the source for the name.

*USRDFNOPT4
Use the user-defined option 4 as the source for the name.

*USRDFNDTA
Use the user-defined data as the source for the name.

For directory files:

*FIRST
Use the part of the file name up to the first period as the source for the name.

*SECOND
Use the part of the file name between the first period and the second period as the source for the name.

*THIRD
Use the part of the file name between the second period and the third period as the source for the name.

*FOURTH
Use the part of the file name between the third period and the fourth period as the source for the name.

Input (INPUT)

Specifies where to find the data to load.

*SPLF
The input data is read from the spooled file specified by the SPLF, JOB, and SPLNBR parameters.

*FILE
The input data is read from the database file specified by the FILE and MBR parameters.

*STMF
The input data is read from the stream file specified by the STMF parameter.

File (FILE)

Specifies the database file that contains data to load.

Qualifier 1: File

file-name
Specify the name of the database file that contains the report data to store. The first character in each line of this data must contain a valid forms control character.

Qualifier 2: Library

*LIBL
All libraries in the job's library list are searched until the first match is found.

*CURLIB
The current library for the job is where the file is located. If no library is specified as the current library for the job, QGPL is used.

library-name
Specify the name of the library where the database file is located.

*LAST

member-name
Specify the name of the database member that contains the data to load.

Stream file (STMF)

Specifies the path to the stream file that contains the data to load.

- When the application data type is LINE or SCS, the file extension must be .lin, .LIN, .line, .LINE, .txt, or .TXT.

Note: The stream file must contain line data where the first character of every record contains one of the ANSI forms control codes.

- When the application data type is AFP, the file extension must be .afp or .AFP.

Note: The stream file must contain an AFP data stream.

Spooled file (SPLF)

Specifies the name of the spooled file to use as input to the load process. This is the file name that was specified by the user program when the file was created, or the name of the printer device file used to create this file.

Specify the name that identifies the user profile under which the job is run.

Spooled file number (SPLNBR)

Specifies, by number, which of the job's spooled files to load.

*ONLY
Only one spooled file in the job has the specified file name; therefore, the number of the spooled file is not necessary.

*LAST
The spooled file with the highest number and the specified file name is used.

*ANY
The spooled file number is not used to determine which spooled file is used. Use this value when the job system name parameter or the spooled file create date and time parameter takes precedence over the spooled file number when selecting a spooled file.

spooled-file-number
Specify the number of the spooled file having the specified file name to use.

Job system name (JOBSYSNAME)

Specifies the name of the system where the job that created the spooled file (JOB parameter) ran. This parameter is considered after the job name, user name, job number, spooled file name, and spooled file number parameter requirements have been met.

*ONLY
There is one spooled file with the specified job name, user name, job number, spooled file name, spooled file number, and spooled file create date and time.

*CURRENT
The spooled file created on the current system with the specified job name, user name, job number, spooled file name, spooled file number, and create date and time is used.

*ANY
The job system name is not used to determine which spooled file is used. Use this value when the spooled file create date and time parameter takes precedence over the job system name when selecting a spooled file.

job-system-name
Specify the name of the system where the job that created the spooled file ran.

Single values

Add Report job name (JOBNAME)

Specifies the job name for the Add Report batch job.

*DFT
The job name is ADDRPT.

*APPGRP
The first 10 characters of the application group name that is specified in the APPGRP keyword are used as the job name. If the APPGRP parameter is one of the special values [*JOBNAME, *SPLFNAME, *USERDATA, *FORMTYPE, *USRDFNOPT1, *USRDFNOPT2, *USRDFNOPT3, *USRDFNOPT4, *USRDFNDTA, *FIRST, *SECOND, *THIRD, *FOURTH] the value is resolved from the spooled file attributes or stream file path.

*APP
The first 10 characters of the application name that is specified in the APP keyword are used as the job name. If the APP parameter is one of the special values [*APPGRP, *JOBNAME, *SPLFNAME, *USERDATA, *FORMTYPE, *USRDFNOPT1, *USRDFNOPT2, *USRDFNOPT3, *USRDFNOPT4, *USRDFNDTA, *FIRST, *SECOND, *THIRD, *FOURTH] the value is resolved from the spooled file attributes or stream file path.

job-name
The name that is specified is used as the job name.

Error option (ERROPT)

Specifies what to do if the load process is not successful.

*RMVRPT
Remove all data loaded up to the point of the failure.

*NORMVRPT
No data is removed. See the system log to determine what was added.

Trace stream file (TRCSTMF)

Specifies the path and stream file name to contain trace data. If you specify a path name, tracing is enabled for this specific occurrence of the command, and ends when the command completes.

A trace provides IBM Software Support with detailed diagnostic information when IBM i logging might not be sufficient. A trace impacts server performance and should only be enabled when requested by IBM Software Support.

*NONE
Trace is not enabled for this specific occurrence of the command.

*GEN
The trace file name is generated automatically based on the input data type and file name. The file extension is '.trc'. The file is placed in the temporary directory of the instance as specified in the ARS.CFG file. The default temporary directory is named TMP and is located in the instance directory.

path-name
Specify the path and stream file name to contain a trace of the load.

Examples for ADDRPTOND

Example 1: Archive Spooled File (Default Instance)

ADDRPTOND APPGRP(CHECKSTMTS) SPLF(CKSTMTPRTF)

This command submits a job to batch that archives a spooled file named CKSTMTPRTF from the current job into a Content Manager OnDemand application/application group named CHECKSTMTS. All other command parameter defaults are used, including the default instance.

Example 2: Archive Spooled File

ADDRPTOND APPGRP(CHECKSTMTS) APP('Account Statements')
SPLF(CKSTMTPRTF) JOB(123456/OPERATOR/NIGHTBATCH)
SPLNBR(*LAST) INSTANCE(ACCTING)

This command submits a job to batch that archives a spooled file named CKSTMTPRTF from a nightly batch job named NIGHTBATCH into a Content Manager OnDemand application named Account Statements within an application group named CHECKSTMTS. The data is archived into an instance named ACCTING.

Example 3: Archive Stream File (Default Instance)

ADDRPTOND APPGRP(INVOICES) INPUT(*STMF)
STMF('/PDFFiles/Inv0214.pdf')

This command submits a job to batch that archives a stream file named Inv0214.pdf located in directory /PDFFiles into a Content Manager OnDemand application named INVOICES within an application group named INVOICES. The data is archived into the default instance.

Example 4: Archive Stream File

ADDRPTOND APPGRP(INVOICES) INPUT(*STMF)
STMF('/PDFFiles/Inv0214.pdf') INSTANCE(ACCTING)

This command submits a job to batch that archives a stream file named Inv0214.pdf located in directory /PDFFiles into a Content Manager OnDemand application named INVOICES within an application group named INVOICES. The data is archived into an instance named ACCTING.
