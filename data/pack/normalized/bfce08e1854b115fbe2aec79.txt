Start Disk Storage Management (STRDSMOND)

Start Disk Storage Management (STRDSMOND)

Last Updated: 2025-04-08

Where allowed to run: All environments (*ALL)

Threadsafe: No | Parameters

Examples

Error messages

The Start Disk Storage Management (STRDSMOND) command starts the Disk Storage Management (DSM) task which manages the movement of Content Manager OnDemand data on disk and between disk and the Archived Storage Manager (ASM). DSM also controls the expiration of data in Content Manager OnDemand. This function can be canceled with a controlled cancel option if enough time is allowed to end what it is currently processing.

Application group (APPGRP)

Specifies the name of the application group to perform management for.

Note: Position the cursor in the application group parameter entry and use the prompt (F4) key to view the list of application group values that are available for the default (*DFT) instance.

The default instance is specified in the QDFTINST data area. The QDFTINST data area can exist in multiple libraries. A search for the QDFTINST data area is performed by using the library list. The first data area that is found is used. If the QDFTINST data area is not found by using the library list, the QUSRRDARS library is searched for the data area. If the data area exists in the QUSRRDARS library, it is used. If the QDFTINST data area is not found, instance QUSROND is used.

*ALL
Management is done for all application groups.

application-group
Only perform management for the named application group.

If the value contains lowercase letters, blanks, or special characters, it must be enclosed in single quotation marks.

Migration options (MGROPT)

Specifies what migration functions are performed.

*DATA
Migrate only Content Manager OnDemand archived data.

*INDEXES
Migrate only Content Manager OnDemand index data.

Note: Migrated indexes cannot be searched without first importing them back into Content Manager OnDemand. Indexes that need to be searched should not be migrated. Before migrating indexes, be sure that is really what you want to do.

*ALL
Migrate both Content Manager OnDemand archived data and indexes.

Note: Migrated indexes cannot be searched without first importing them back into Content Manager OnDemand. Indexes that need to be searched should not be migrated. Before migrating indexes, be sure that is really what you want to do.

*NONE
No migrations are done.

Hold threshold (HLDTHLD)

When using Enhanced Retention Management, specifies a threshold value that determines if and when you want Content Manager OnDemand to reload loads during Disk Storage Management (DSM) processing. The reload would retain only the documents in a load that currently have a hold associated with them. Any documents in the load that are eligible for expiration that do not have a hold would be deleted. If a high percentage of the documents in the load are held, then reloading the data is not recommended because very little space is reclaimed after the reload. If a low percentage of the documents in the load are held, consider setting the Hold threshold (HLDTHLD) parameter to a value that can cause a reload to occur, which can reduce the space used due to the smaller load size. The reload takes time and system resources, but the result is a smaller load stored in Content Manager OnDemand.

When DSM processes a load, it calculates the percentage of documents within the load that have a hold. If the percentage of held documents falls below the threshold value specified, Content Manager OnDemand reloads the load and generates a new load ID or report ID to identify the smaller load. For example, if you specify HLDTHLD(20), and less than 20 percent of documents in a load have a hold, then Content Manager OnDemand reloads the load.

For a more complex example, assume you have a load with 100 documents and you specify HLDTHLD(50). When Content Manager OnDemand processes a load, if the percentage of documents with a hold is less than 50 percent, Content Manager OnDemand reloads the load. The following list describes how Content Manager OnDemand functions as the number of documents with holds increases for this example:

- One document has a hold. The actual percentage is 1 percent. Content Manager OnDemand reloads the load. Only one document belongs to the new load.

- Forty nine documents have a hold. Therefore, the actual percentage is 49 percent. Content Manager OnDemand reloads the load. Forty nine documents belong to the new load.

- Fifty documents have a hold. The actual percentage is 50 percent. Content Manager OnDemand does not reload the load.

- Fifty one documents have a hold. The actual percentage is 51 percent. Content Manager OnDemand does not reload the load.

- No documents have a hold. The actual percentage is 0 percent. This is a special case. Even though 0 percent is less than 50 percent, Content Manager OnDemand does not reload the load, because all documents are eligible for expiration, and there would be nothing left to reload.

*NONE
Content Manager OnDemand does not reload any loads.

1 - 100
Specify the percentage of held documents within a load, between 1 and 100 percent, under which a reload of the load is performed.

Run ASM (STRASMOND)

Specifies whether to run the Archived Storage Management process after the Disk Storage Management process is finished.

Note: If Archived Storage Management runs, reports that it generates are also saved in the Content Manager OnDemand system log.

*YES
Run the Archived Storage Management process if no errors occur during the Disk Storage Management process.

*FORCE
Run the Archived Storage Management process regardless of whether errors occur during the Disk Storage Management process.

*NO
Do not run the Archived Storage Management process.

Force ASM to end (ENDASM)

Specifies if the Archived Storage Management (ASM) process is forced to end, and if so, when it ends.

Note: If ASM completes the movement of all eligible data before the specified ending time, it ends before the specified number of hours or end time occurs.

*NO
Do not force the ASM process to end. ASM ends when it finishes processing all data that is eligible to move from one migration policy level to the next.

*NBRHRS
The ASM process is forced to end after it runs for the number of hours specified by the NBRHRS parameter. ASM completes the movement of the data that is currently being processed before it ends.

*ENDTIME
The ASM process is forced to end at the time specified by the ENDTIME parameter. ASM completes the movement of the data that is currently being processed before it ends.

Top

Number of hours to run (NBRHRS)

Specifies how many hours ASM runs before being forced to end.

8
ASM is forced to end after 8 hours.

1-999
ASM runs from 1 to 999 hours.

Top

Time to end (ENDTIME)

Specifies the time when ASM is forced to end.

Note: If the ENDTIME is after the current time, ASM is forced to end at the time specified by ENDTIME today. If the ENDTIME is before the current time, ASM is forced to end at that time tomorrow.

230000
ASM is forced to end at 11:00 p.m.

ending-time
Specify the time that ASM is forced to end. The time is specified in 24-hour format and can be specified with or without a time separator:

- Without a time separator, specify a string of 4 or 6 digits (hhmm or hhmmss) where hh = hours, mm = minutes, and ss = seconds. Valid values for hh range from 00 to 23. Valid values for mm and ss range from 00 to 59.

- With a time separator, specify a string of 5 or 8 digits where the time separator specified for your job is used to separate the hours, minutes, and seconds. If the STRASMOND command is entered from the command line, the string must be enclosed in single quotation marks. If a time separator other than the separator specified for your job is used, this command fails.

Examples for STRDSMOND

Example 1: Simple Example

STRDSMOND

This command submits a job to batch that starts the Content Manager OnDemand Disk Storage Management (DSM) task which manages the movement of Content Manager OnDemand data on disk and between disk and the Archived Storage Manager (ASM). When issued with no parameters specified, this command processes data for ALL defined application groups in the default instance, migrating data and expiring both data and indexes. Additionally, with no parameters specified as in this example, it automatically runs ASM after the DSM processing finishes.

Example 2: More Complex Example

STRDSMOND APPGRP(CHECKSTMTS) INSTANCE(ACCTING)

This command is similar to Example 1 but the Disk Storage Management process is run only for the application group named CHECKSTMTS within the ACCTING instance.
