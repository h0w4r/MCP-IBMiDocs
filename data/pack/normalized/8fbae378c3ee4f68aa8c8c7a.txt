Change in the handling of date literals with 2-digit years in the source for CRTCMD

Last Updated: 2025-10-07

In releases prior to IBM® i 7.6, when the source for a
command had a PARM or ELEM command with TYPE(*DATE), date literals with 2-digit years were assumed
to represent a date in the years 1940 – 2039.

Starting in IBM i 7.6, date literals with 2-digit years are
interpreted according to the base year of the job when the command is compiled.

For example, the following PARM command uses a date literal to set the default value for the
parameter. When the default value has 6 digits, the format is mmddyy, so the literal value 013141
represents the date January 31, ’41.

PARM KWD(DATE1) TYPE(*DATE) DFT(013141)

If the base year of the job is 1940 at compile time, date literals with 2-digit years are assumed
to represent a date in the years 1940 – 2039, so the default value for the parameter is January 31,
1941.

If the base year of the job is 1970 at compile time, date literals with 2-digit years are assumed
to represent a date in the years 1970 – 2069, so the default value for the parameter is January 31,
2041.
