Example 4: Specifying the key field

The example shows how several record formats
function as a set. In this example, assume that an employee has repeated a
class. To sequence two records with the same values for EMPNBR and CLSDTE,
a third key field, DATE, is specified in record format CLSHST.

However, DATE cannot be specified in the next available key position
(position 3) because JOBDTE and ACTDTE appear in that position for other formats.
If DATE is specified in this position, the attributes of DATE are compared
with the attributes of CLSHST and JOBHST, and the key definitions are rejected.
To
obtain the sequencing necessary, specify *NONE before DATE, displacing DATE
to key position 4.

Specifying DATE in key position 4 enables records from physical
file CLSHSTP with identical values for EMPNBR and CLSDTE to be merged and
sequenced according to the value for DATE.
Note: Because values are actually
placed in the keys to ensure the sequencing in the previous examples, duplicate
key values are not always predictable when *NONE is needed for logical files
with more than one record format.
