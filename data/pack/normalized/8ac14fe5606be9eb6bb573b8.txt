Change Policy Level Date (CHGPLDOND)

Change Policy Level Date (CHGPLDOND)

Last Updated: 2025-04-08

Where allowed to run: All environments (*ALL)

Threadsafe: No | Parameters

Examples

Error messages

The Change Policy Level Date (CHGPLDOND) command changes the next level date to a new date for Content Manager OnDemand objects that are at the named level in the named migration policy. Only objects in the specified date range or the specific objects for the entered report ID are changed.

Policy (POLICY)

Specifies the migration policy that contains the level to change.

This is a required parameter.

Note: Position the cursor in the policy parameter entry and use the prompt (F4) key to view the list of policy values that are available for the default (*DFT) instance.

The default instance is specified in the QDFTINST data area. The QDFTINST data area can exist in multiple libraries. A search for the QDFTINST data area is performed by using the library list. The first data area that is found is used. If the QDFTINST data area is not found by using the library list, the QUSRRDARS library is searched for the data area. If the data area exists in the QUSRRDARS library, it is used. If the QDFTINST data area is not found, instance QUSROND is used.

name
Specify the name of the migration policy.

Top

Processing option (OPTION)

Specifies the type of processing to perform.

*DATE
Objects within the specified date range are processed and are assigned the specified new date.

*RPTID
Objects with the specified report ID are processed and are assigned the specified new date.

*DAYS
Objects within the specified date range are processed and are assigned a new date based on their old date plus or minus the specific number of days provided.

Top

Report ID (RPTID)

Specifies the report ID of the report to process.

The report ID is also known as the load ID and is found in the Content Manager OnDemand System Load folder or the System Log folder in the message text for message number 87, both generated when an input file is successfully loaded into the system. The report ID contains the value that Content Manager OnDemand generates to uniquely identify an input file, such as 5547-4-0-2FAA-20130313000000-20130313000000-5548. The report ID contains the following parts:

agid-pri_nid-sec_nid-docid-start_date-stop_date-aid

agid
Application group identifier.

pri_nid
Primary storage node.

sec_nid
Secondary storage node.

docid
Document identifier.

start_date
First date in the report. The format of the date is YYYYMMDDHHMMSS. Loads created with versions of Content Manager OnDemand prior to server version 9.0 use an older, internal date format for this part.

Note: If you do not know the start date, the value of this part can be specified as 0.

stop_date
Last date in the report. The format of the date is YYYYMMDDHHMMSS. Loads created with versions of Content Manager OnDemand prior to server version 9.0 use an older, internal date format for this part.

Note: If you do not know the stop date, the value of this part can be specified as 0.

aid
Application identifier. This part is optional.

Level (LEVEL)

Specifies the level that contains the objects to change.

This is a required parameter.

name
Specify the name of the level.

New date (NEWDATE)

Specifies the new date that objects can move from the level.

This is a required parameter if the OPTION parameter is set to *DATE or *RPTID.

date
Specify the new date in job date format. If date separator characters are specified, enclose the date value between single quotation marks.

Top

Number of days (DAYS)

Specifies the number of days to add or subtract from the current next level date. You can specify a positive number such as 30 to increase the number of days that the objects remain in the specified policy level. You can specify a negative number such as -30 to decrease the number of days that the objects remain in the specified policy level.

This is a required parameter if the OPTION parameter is set to *DAYS.

Top

Level date range (LVLDATE)

Specifies the earliest and latest dates of the level that are changed to the new date.

Element 1: From date

*BEGIN
Start with the earliest available date.

*CURRENT
Today's date is used.

date
Specify the starting date in job date format. If date separator characters are specified, enclose the date value between single quotation marks.

Element 2: To date

*END
End with the latest available date.

*CURRENT
Today's date is used.

date
Specify the ending date in job date format. If date separator characters are specified, enclose the date value between single quotation marks.

Top

Instance (INSTANCE)

Specifies the name of the Content Manager OnDemand instance used.

*DFT
The default Content Manager OnDemand instance is used.
The default instance is specified in the QDFTINST data area. The QDFTINST data area can exist in multiple libraries. A search for the QDFTINST data area is performed by using the library list. The first data area that is found is used. If the QDFTINST data area is not found by using the library list, the QUSRRDARS library is searched for the data area. If the data area exists in the QUSRRDARS library, it is used. If the QDFTINST data area is not found, instance QUSROND is used.

instance-name
Specify the name of the instance that is used.

Examples for CHGPLDOND

Example 1: Changing Next Level Date for Level LVL1

CHGPLDOND POLICY(TESTPOLICY) OPTION(*DATE) LEVEL(LVL1)
NEWDATE(*CURRENT)

This command changes the next level date of all objects in the migration policy named TESTPOLICY at level LVL1 for the default instance to today's date. The objects are moved to the next level the next time the Start Archived Storage Management (STRASMOND) command is run.

Example 2: Changing Next Level Date with Date Range

CHGPLDOND POLICY(TESTPOLICY) LEVEL(LVL1) OPTION(*DATE)
NEWDATE(*CURRENT) LVLDATE(*BEGIN '05/10/21')
INSTANCE(TEST)

This command changes the next level date of those objects in the migration policy TESTPOLICY at level LVL1 for the instance TEST that have a date less than or equal to 05/10/21. The date for those objects is changed to today's date.

Example 3: Changing Next Level Date for a specific report

CHGPLDOND POLICY(TESTPOLICY) OPTION(*RPTID)
RPTID('1220-1-0-8FAA-20130420120000-20130421120000')
LEVEL(LVL1) NEWDATE(*CURRENT) INSTANCE(TEST)

This command changes the next level date of the report that matches the report ID for the migration policy TESTPOLICY at level LVL1 for the instance TEST. The new date is changed to today's date.

Example 4: Changing Next Level Date by 365 days

CHGPLDOND POLICY(TESTPOLICY) OPTION(*DAYS) LEVEL(LVL1) DAYS(365)

This command adds 365 days to the next level date of all objects in the migration policy named TESTPOLICY at level LVL1 for the default instance. If the DAYS parameter is DAYS(-365), it subtracts 365 days from the current next level date.
