The Create Instance (CRTINSTOND) command creates a Content Manager OnDemand instance.

A Content Manager OnDemand instance is a logical server environment with its own library containing a unique set of database files. An instance is defined in the ARS.INI file by naming the instance (which identifies the name of the library used by the instance). All of the database files that belong to an instance are encoded in one and only one coded character set identifier (CCSID).

You can run multiple instances on the same server, with each instance configured differently:

- To have separate test and production environments

- To have databases using different CCSIDs

When you work with more than one instance, you must identify the instance name when you run Content Manager OnDemand commands (such as ADDRPTOND and STRMONOND).

Each instance has different security from other instances on the same system. You must define users and groups to each instance and set application group and folder permissions for users of each instance. Each instance has its own system log.

Instance (INSTANCE)

Specifies the name of the instance to create.

This is a required parameter.

instance-name
Specify the name of the instance that is created.
Be sure that no library, user profile, or authorization list by that name already exists. Further, the instance name cannot start with the letter Q (except for QUSROND), and cannot be named CONFIG, GUI, or WWW.

Specifies the language identifier used for this instance.

Note: IBM i might support additional languages which are not supported by Content Manager OnDemand system log messages. System log messages are in English when an instance uses a language identifier that is not supported.

*SYSVAL

Port number (PORT)

Specifies the TCP/IP port on which the instance server listens to receive requests from an OnDemand client.

*DFT
The value of *DFT uses the default port of 1445. Only one server can listen on a particular port at any given time. If you need to run multiple instances concurrently, you must specify a port that is not being used on your system for some other purpose.

1024-65535
Specify the port on which the instance server listens to receive requests from an OnDemand client. Valid values range from 1024 through 65535.

Note: You can use the Work with TCP/IP Network Status (WRKTCPSTS) command with OPTION(*CNN) to see what IPv4 ports are currently in use on your system. You can use the Work with TCP/IP Network Status (WRKTCPSTS) command with OPTION(*CNN6) to see what IPv6 ports are currently in use on your system.

Autostart instance server (AUTOSTART)

Specifies whether to automatically start the instance server when running the Start TCP/IP Server (STRTCPSVR) command with SERVER(*ONDMD) and INSTANCE(*AUTOSTART) specified. If INSTANCE(*AUTOSTART) is not specified when running the STRTCPSVR command with SERVER(*ONDMD), this parameter is ignored.

*NO
Do not start the instance server when the STRTCPSVR SERVER(*ONDMD) with INSTANCE(*AUTOSTART) command is run.

*YES
Start the instance server when the STRTCPSVR SERVER(*ONDMD) with INSTANCE(*AUTOSTART) command is run.

ASP number (ASP)

Specifies the number of the system or basic user auxiliary storage pool (ASP) where storage for the instance library is allocated. For instances created in an ASP, all objects in the instance library must be in the same ASP as the library. When a value other than *ASP is specified for the ASP device (ASPDEV) parameter, *ASPDEV must be specified for the ASP number (ASP) parameter.

1
The storage space for the instance library is allocated from the system auxiliary storage pool ASP 1.

*ASPDEV
The storage for the instance library is allocated from the primary or secondary ASP specified for the ASPDEV parameter.

number
Specify a value ranging from 1 through 32 that is the number of the system or basic user ASP.

Top

ASP device (ASPDEV)

Specifies the auxiliary storage pool (ASP) device name where storage is allocated for the instance library. If a value other than *ASPDEV is specified for the ASP number (ASP) parameter, the ASP device (ASPDEV) parameter must be set to *ASP. Other values for the ASPDEV parameter are valid if the ASP parameter is set to *ASPDEV.

*ASP
The storage for the instance library is allocated from the system or basic user ASP specified for the ASP parameter.

*ASPGRPPRI
The storage for the instance library is allocated from the primary ASP of the thread's ASP group. If no ASP group is associated with the thread, an error message is sent.

*SYSTEM
The storage for the instance library is allocated from the system ASP (ASP 1).

name
Specify the name of a primary or secondary ASP device. The storage for the instance library is allocated from the primary or secondary ASP. The primary or secondary ASP must have been activated (by varying on the ASP device) and have a status of 'Available'.

Note: To specify a specific auxiliary storage pool (ASP) device name, you must have use (*USE) authority for each ASP device in the ASP group.

Server security (SECURITY)

This specifies how security is administered for this instance.

You can select to use IBM i administered user profiles and passwords as the Content Manager OnDemand user IDs and passwords or you can select to use user IDs and passwords that are administered by Content Manager OnDemand.

*SYSTEM
Use IBM i user profiles and passwords as the Content Manager OnDemand user IDs and passwords. This value makes it simpler for your end users because they do not have to maintain multiple user IDs and passwords.

*ONDMD
Use Content Manager OnDemand managed user IDs and passwords. When this is specified, your Content Manager OnDemand user IDs and passwords have no relationship to IBM i user profiles and passwords. All management of Content Manager OnDemand user IDs and passwords must be performed using the OnDemand Administrator client or batch administration (the ARSXML program).

Default instance (DFTINST)

Specifies that this instance is set as the new default (*DFT) instance in the QDFTINST data area in library QUSRRDARS.

*NO
This instance does not become the default (*DFT) instance.

*YES
This instance becomes the default (*DFT) instance.

Note: If the QDFTINST data area does not exist in library QUSRRDARS, it is created. The default (*DFT) instance specified in the QDFTINST data area in library QUSRRDARS can be overridden by creating another QDFTINST data area in a user library which can then be included in the library list of any Content Manager OnDemand job that requires a different default instance.

Examples for CRTINSTOND

Example 1: Create an Instance

CRTINSTOND INSTANCE(ONDTEST) LANGID(ENU)
LOCALE('/QSYS.LIB/EN_US.LOCALE')
PORT(*DFT) AUTOSTART(*YES) SECURITY(*SYSTEM)

This command submits a job to batch that creates an instance named ONDTEST. The instance is created with a language ID of US English and with a US English locale. The instance server listens on the default TCP/IP port number and is started automatically when the Start TCP/IP Server (STRTCPSVR) command with SERVER(*ONDMD) and INSTANCE(*AUTOSTART) parameters is specified. The instance server uses IBM i user profiles and passwords.

Example 2: Create an Instance which uses Content Manager OnDemand Managed User IDs and Passwords

CRTINSTOND INSTANCE(ONDPROD) LANGID(DEU)
LOCALE('/QSYS.LIB/DE_DE.LOCALE')
PORT(1450) AUTOSTART(*YES) ASP(*ASPDEV)
ASPDEV(ASP01) SECURITY(*ONDMD) DFTINST(*YES)
STRSVR(*YES)

This command submits a job to batch that creates an instance named ONDPROD. The instance is created with a language ID of German and with a locale which supports the Euro. The instance server listens on TCP/IP port 1450 and is started automatically when the Start TCP/IP Server (STRTCPSVR) command with SERVER(*ONDMD) and INSTANCE(*AUTOSTART) parameters is specified. The instance server uses user IDs and passwords which are managed by using the OnDemand Administrator client. The instance library is created in an independent auxiliary storage pool (IASP) named IASP1. The ONDPROD instance becomes the default instance server (*DFT) that is used by other Content Manager OnDemand commands. The instance server is started after it is created.

Example 3: Create a UTF-8 Instance

CRTINSTOND INSTANCE(ONDTEST) LANGID(ENU)
LOCALE('/QSYS.LIB/EN_US.LOCALE')
PORT(*DFT) AUTOSTART(*NO) SECURITY(*SYSTEM)
DBFCCSID(*UTF8)

This command submits a job to batch that creates an instance named ONDTEST. The instance is created with a language ID of US English and with a US English locale. All data is stored in UTF-8 (CCSID 1208) rather than the CCSID of the named locale. The instance server listens on the default TCP/IP port number. The instance server uses IBM i user profiles and passwords.

Example 4: Create an Instance that Uses SSL

CRTINSTOND INSTANCE(ONDPROD)
LANGID(FRA)
LOCALE('/QSYS.LIB/FR_FR.LOCALE')
PORT(1507) AUTOSTART(*YES)
DBFCCSID(*UTF8)
USESSL(*YES) SSLPORT(1607)
SSLKEYF('/QIBM/UserData/OnDemand/CONFIG/CMOD.kdb')
SSLKEYPWD(AZERTY7) SSLKEYLBL(CMODSSL)
CLNTUSESSL(*NO)

This command submits a job to batch that creates an instance named ONDPROD. The instance is created with a language ID of French and with a locale which supports the Euro. All data is stored in UTF-8 (CCSID 1208) rather than the CCSID of the named locale. The instance server uses SSL on port 1607. The SSL certificates and keys are contained in a file named CMOD.kdb which is located in the CONFIG directory. The SSL key password is AZERTY7. The SSL key label is CMODSSL. Server-side clients do not use SSL.
