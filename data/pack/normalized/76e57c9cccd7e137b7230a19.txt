Start Monitor (STRMONOND)

Start Monitor (STRMONOND)

Last Updated: 2025-04-08

Where allowed to run: All environments (*ALL)

Threadsafe: No | Parameters

Examples

Error messages

The Start Monitor (STRMONOND) command automates the loading of data into Content Manager OnDemand. You specify the name of an output queue or directory for Content Manager OnDemand to monitor. The spooled files in the output queue, or the files in the directory, are then processed automatically by the Add Report (ADDRPTOND) command.

Once files are processed, they are controlled by the value of the DLTSPLF parameter. Spooled files are additionally controlled by the settings of the ERROUTQ and the PRCOUTQ parameters. If you specify DLTSPLF(*YES), then successfully processed files are deleted. If you specify DLTSPLF(*NO), then successfully processed spooled files are moved to the output queue named in the PRCOUTQ parameter; successfully processed directory files have '.PRC' added to the end of the file name. Unsuccessfully processed files are never deleted. Spooled files are moved to the output queue specified in the ERROUTQ parameter; directory files have '.ERR' added to end of the file name.

You can end the monitor by:

- Specifying a method for the monitor to end automatically.

- Running the ENDMONOND command.

- Using the Content Manager OnDemand administration functions in IBM Navigator for i. Select Active Monitor Jobs and choose the End action.

- Ending the monitor job using the ENDJOB command. Specify OPTION(*CNTRLD) and DELAY(999999). The job ends as soon as the monitor finishes processing the current file.

- Limiting the number of errors that can occur before the monitor is ended. The monitor job ends as soon as the maximum number of consecutive or total errors occur. Errors might include application group name or application name not found, or indexing failures such as trigger, field, or index not found, for example.

Type (TYPE)

Specifies the type of monitor.

*OUTQ
Monitor the output queue named in the OUTQ parameter.

*DIR
Monitor the directory named in the DIR parameter. This type of monitor processes .IND or .PDF files.

*DIR2
Monitor the directory named in the DIR parameter. This type of monitor processes .ARD files.

*DIR3
Monitor the directory named in the DIR parameter. This type of monitor processes .AFP, .LIN, .LINE, .TXT, and .PDF files.

Directory (DIR)

Specifies the directory to monitor. A value must be provided if TYPE(*DIR), TYPE(*DIR2), or TYPE(*DIR3) is specified.

When a directory is monitored, the monitor looks for files to process in that directory. Each file that is found in the directory is processed. In most cases the file names must contain the application group and application name. See help for the Application group (APPGRP) and Application (APP) parameters for more information on obtaining those names. For example, 'CHECKSTMTS.BIGSTMTS.data'. The monitor can use any one of the first 4 parts of the file name based on the values you specify for the APPGRPSRC and APPSRC parameters. When a file is processed successfully, '.PRC' is appended to the file name unless you have specified DLTSPLF(*YES). If the load fails or if the values determined for application group and application are not valid, '.ERR' is appended to the file name. Files that end in .PRC or .ERR are not processed.

End monitor automatically (ENDMON)

Specifies if the monitor automatically ends and how.

*NO
Do not end the monitor automatically.

*NOINPUT
The monitor ends when the monitored output queue or directory has no more files to process.

Note: Only spooled files in the ready state are processed.

*NBRHRS
The monitor ends after it runs the number of hours specified on the NBRHRS parameter.

*ENDTIME
Specify that the monitor ends at the time specified on the ENDTIME parameter.

Top

Number of hours to run (NBRHRS)

Specifies how many hours the monitor runs before automatically ending.

8
The monitor automatically ends after 8 hours.

1-999
The monitor runs from 1 to 999 hours.

Top

Time to end (ENDTIME)

Specifies the time when the monitor automatically ends.

230000
The monitor automatically ends at 11:00 pm.

ending-time
Specify the time that the monitor ends. The time is specified in 24-hour format and can be specified with or without a time separator:

- Without a time separator, specify a string of 4 or 6 digits (hhmm or hhmmss) where hh = hours, mm = minutes, and ss = seconds. Valid values for hh range from 00 to 23. Valid values for mm and ss range from 00 to 59.

- With a time separator, specify a string of 5 or 8 digits where the time separator specified for your job is used to separate the hours, minutes, and seconds. If this command is entered from the command line, the string must be enclosed in single quotation marks. If a time separator other than the separator specified for your job is used, this command fails.

Note: If the ENDTIME is after the current time, the monitor ends at the time specified by ENDTIME today. If the ENDTIME is before the current time, the monitor ends at that time tomorrow.

Check interval (CHKITV)

Specifies, in seconds, how long the monitor waits before it checks the monitored directory again for a file to process. The wait time specified only applies when there are no more files to process in the monitored directory. This parameter only applies when the TYPE parameter is set to *DIR, *DIR2, or *DIR3.

Once this time has expired, a check is made to see if:

- The current time is later than the time specified on the ENDTIME parameter.

- The number of hours specified on the NBRHRS parameter has passed.

- The ENDMONOND command has been issued.

- The ENDJOB commmand has been issued for this job with the OPTION parameter set to *CNTRLD.

30
The monitor waits 30 seconds before checking again to see if there is a file to process.

time-interval
Specify the number of seconds to wait before checking the monitored directory again for a file to process. The value must be between 1 and 90 seconds.

Note: Specifying a small value causes the monitor to consume more processing time because it checks more frequently for a file to process.

Examples for STRMONOND

Example 1: Start a Content Manager OnDemand Monitor for an Output Queue

STRMONOND OUTQ(QUSRRDARS/ONDEMANDQ)

This command submits a job to batch that monitors for spooled files that to archive into Content Manager OnDemand. When issued with no other parameters, the monitor uses the spooled file name attribute of the spooled file as both the application group name and application name. Spooled files that do not archive successfully are moved to the ONDERR output queue in QUSRRDARS library. Spooled files that archive successfully are not deleted; they are moved to the ONDPROC output queue in QUSRRDARS library. This command submits the monitor job without any specified end criteria, and processes within the default instance.

Example 2: Start a Content Manager OnDemand Monitor for an Output Queue Which Ends at a Specific Time

STRMONOND OUTQ(QUSRRDARS/ONDEMANDQ)
APPGRPSRC(*SPLFNAME *FORMTYPE) APPSRC(*USERDATA)
DLTSPLF(*YES) ENDMON(*ENDTIME) ENDTIME(235900)
INSTANCE(ACCTING)

This command submits a job to batch that monitors for spooled files to archive into Content Manager OnDemand. The monitor uses the spooled file name and then the form type attributes of the spooled file (in that order) for use as the application group name. The monitor uses the user data attribute of the spooled file as the application name. Successfully processed spooled files are deleted automatically; spooled files that do not archive successfully are moved to the ONDERR output queue in QUSRRDARS library. In this example, the monitor ends at one minute before midnight of the current day. All processing occurs within the ACCTING instance.

Example 3: Start a Content Manager OnDemand Monitor for a Directory

STRMONOND TYPE(*DIR) DIR('/mydir') APPGRPSRC(*SECOND)
APPSRC(*THIRD) DLTSPLF(*YES) INSTANCE(ACCTING)

This command submits a job to batch that monitors for stream files to archive into Content Manager OnDemand. The monitor uses the second part of the file name as the application group name and the third part of the file name as the application name. Successfully processed stream files are deleted automatically; stream files that do not archive successfully are retained in their current directory with the suffix of .ERR appended to the end of the file name. All processing occurs within the ACCTING instance.
