Start Archived Storage Mgmt (STRASMOND)

Last Updated: 2025-04-08
Where allowed to run: All environments (*ALL)
Threadsafe: No 		Parameters
Examples
Error messages

The Start Archived Storage Mgmt (STRASMOND) command starts the Archived Storage Management (ASM) process which manages the movement of Content Manager OnDemand data within the ASM defined levels. This function can be canceled with a controlled cancel option if enough time is allowed to end what it is currently processing.

SQL Server Mode is enabled for any job that runs this command. This is only a concern if the command is run interactively. If any SQL statements have been processed in the interactive job before STRASMOND is run, STRASMOND fails with SQL errors. To avoid this problem either always submit STRASMOND to batch (the default) or signoff and sign back on before running STRASMOND interactively.

The reports generated by the command are also saved in the Content Manager OnDemand system log.

Policy (POLICY)

Specifies the name of the policy against which Archived Storage Management performs the requested functions.

Note: Position the cursor in the policy parameter entry and use the prompt (F4) key to view the list of policy values that are available for the default (*DFT) instance.

The default instance is specified in the QDFTINST data area. The QDFTINST data area can exist in multiple libraries. A search for the QDFTINST data area is performed by using the library list. The first data area that is found is used. If the QDFTINST data area is not found by using the library list, the QUSRRDARS library is searched for the data area. If the data area exists in the QUSRRDARS library, it is used. If the QDFTINST data area is not found, instance QUSROND is used.

*ALL
All policies are used. All eligible data is managed.
policy-name
Specify the name of the policy that ASM processes. Only the eligible data that is associated with the named policy is managed.

Process to run (PROCESS)

Specifies if the Archived Storage Management (ASM) process does migration processing, expiration processing, or both. You might want to separate these functions if you are concerned with how long ASM processing takes.

*ALL
Both migration and expiration processing are done.
*MIGRATION
Only migration processing is done.
*EXPIRATION
Only expiration processing is done.

Force ASM to end (ENDASM)

Specifies if the Archived Storage Management (ASM) process is forced to end, and if so, when it ends.

Note: If ASM completes the movement of all eligible data before the specified ending time, it ends before the specified number of hours or end time occurs.

*NO
Do not force the ASM process to end. ASM ends when it finishes processing all data that is eligible to move from one migration policy level to the next.
*NBRHRS
The ASM process is forced to end after it runs for the number of hours specified by the NBRHRS parameter. ASM completes the movement of the data that is currently being processed before it ends.
*ENDTIME
The ASM process is forced to end at the time specified by the ENDTIME parameter. ASM completes the movement of the data that is currently being processed before it ends.
Top

Number of hours to run (NBRHRS)

Specifies how many hours ASM runs before being forced to end.

8
ASM is forced to end after 8 hours.
1-999
ASM runs from 1 to 999 hours.
Top

Time to end (ENDTIME)

Specifies the time when ASM is forced to end.

Note: If the ENDTIME is after the current time, ASM is forced to end at the time specified by ENDTIME today. If the ENDTIME is before the current time, ASM is forced to end at that time tomorrow.

230000
ASM is forced to end at 11:00 p.m.
ending-time
Specify the time that ASM is forced to end. The time is specified in 24-hour format and can be specified with or without a time separator:
  • Without a time separator, specify a string of 4 or 6 digits (hhmm or hhmmss) where hh = hours, mm = minutes, and ss = seconds. Valid values for hh range from 00 to 23. Valid values for mm and ss range from 00 to 59.
  • With a time separator, specify a string of 5 or 8 digits where the time separator specified for your job is used to separate the hours, minutes, and seconds. If the STRASMOND command is entered from the command line, the string must be enclosed in single quotation marks. If a time separator other than the separator specified for your job is used, this command fails.

The default instance is specified in the QDFTINST data area. The QDFTINST data area can exist in multiple libraries. A search for the QDFTINST data area is performed by using the library list. If the data area exists in the QUSRRDARS library, it is used. If the QDFTINST data area is not found, instance QUSROND is used.

instance-name
Specify the name of the instance that is used.

ASM job name (JOBNAME)

Specifies the job name for the ASM batch job.

*DFT
The first 10 characters of the policy name that is specified in the POLICY keyword are used as the job name. If the policy name that is specified is *ALL, the job name is ASM.
*POLICY
The first 10 characters of the policy name that is specified in the POLICY keyword are used as the job name. If the policy name that is specified is *ALL, the job name is ASM.
*INSTANCE
The instance name specified in the INSTANCE keyword is used as the job name. If *DFT is specified for the INSTANCE keyword, the default instance is determined and that name is used as the job name.
job-name
The name that is specified is used as the job name.

Examples for STRASMOND

Example 1: Simple Example 

STRASMOND

This command submits a job to batch that starts the Content Manager OnDemand Archived Storage Management (ASM) process which manages the movement of data within the defined levels of archive media. When issued with no parameters specified, this command processes data for ALL defined storage management policies for the default instance, and runs both migration and expiration processing.

Example 2: More Complex Example 

STRASMOND POLICY(APDATAPOL) PROCESS(*MIGRATION)
          INSTANCE(ACCTING)

This command is similar to Example 1 but only processes data associated with the APDATAPOL policy definition in the ACCTING instance and only runs migration processing.
