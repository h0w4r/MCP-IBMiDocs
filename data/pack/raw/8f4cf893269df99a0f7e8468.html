A global constant parameter cannot be modified in a sub-procedure

Last Updated: 2025-10-07

Prior to IBM i 7.6, when a global parameter defined with the CONST keyword was modified in a sub-procedure by some statements, the compiler failed to issue a diagnostic message for several scenarios.

Starting in the base of release 7.6 for TGTRLS(*CURRENT), the compiler does not allow an operation in a sub-procedure that modifies a global constant parameter. A diagnostic message is now issued when a constant global parameter is specified for the following scenarios:

  • The first operand of DATA-INTO: Message RNF7191 is now issued. ("The first operand of DATA-INTO cannot be modified.")
  • The first operand of DEALLOC: Message RNF7261 is now issued. . ("The Result-Field operand is not valid for the specified operation.")
  • The first operand of EVAL-CORR: Message RNF7353 is now issued. ("The target operand of EVAL-CORR is not valid.")
  • The first operand of ON-EXIT: Message RNF5438 is now issued. ("The operand for the ON-EXIT operation code is not valid.")
  • The first operand of XML-INTO: Message RNF5354 is now issued.(" The first operand of XML-INTO cannot be modified.")
  • The result field of DSPLY in a free-form statement: Message RNF7261 is now issued. ("The Result-Field operand is not valid for the specified operation.")

For target releases V7R4M0 and V7R5M0, you can add environment variable, QIBM_RPG_CHK_ALL_CONST_IN_SUBPROC, with a value of 'Y', to cause the compiler to issue a diagnostic message when a global constant parameter is modified in a sub-procedure.
