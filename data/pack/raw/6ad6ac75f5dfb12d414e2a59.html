The CCSID of the initialization value for INZ(*EXTDFT) is now handled correctly

Last Updated: 2025-10-07

Prior to IBM® i 7.6, when an externally-described data structure or subfield was defined with INZ(*EXTDFT), the initialization value was not always correct when the target CCSID (TGTCCSID parameter) for CRTBNDRG or CRTRPGMOD was not the same as the CCSID of the initialization data from the externally-described file.

Starting in the base of IBM i 7.6 for TGTRLS(*CURRENT), the compiler handles the CCSID of the initialization values correctly.

This may cause new compile-time errors for the initialization values of the sub-fields:

  • When the data structure is defined with CCSID(*EXACT), and the initialization data cannot be converted to the CCSID of the subfield, message RNF0673 is issued. ("Some characters could not be converted from the source-file CCSID to the required CCSID.")
  • When the data structure is defined with CCSID(*EXACT), and the initialization value of a subfield with CCSID(1208) has more bytes length of the subfield, RNF3496 is issued ("Initialization value exceeds maximum literal length.")

For target IBM i 7.4 and IBM i 7.5, you can add environment variable, QIBM_RPG_CORRECT_INZ_EXTDFT_CHAR, with a value of 'Y', to cause the compiler to handle the CCSID of the initialization data correctly.
